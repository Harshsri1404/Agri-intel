# AgriIntel — Farmer Credit Intelligence API

A FastAPI backend that estimates a farmer's income, produces a 0-100 **AgriScore**, suggests a loan amount, flags weather-driven NPA risk, and generates a one-page **Farmer Financial Health Card** (PDF) for bank officers.

> **Status: student project / prototype.** It is a decision-support tool, **not** a lending product. Final credit decisions rest with the bank officer. Do not use it on real farmers without validating the models on real loan outcomes.

Built by Harsh Srivastava, IIT Guwahati.

## Sample output

[`examples/demo_farmer_health_card.pdf`](examples/demo_farmer_health_card.pdf) — generated by `python demo.py` using the built-in rule-based demo mode.

## Features (20 routes)

| Area | Endpoint |
|------|----------|
| Income prediction | `POST /predict/income` |
| AgriScore (0-100) | `POST /predict/score` |
| Repayment score | `POST /predict/repayment` |
| Full assessment (all-in-one) | `POST /predict/full` |
| Loan amount recommender | `POST /predict/loan-amount` |
| Batch upload (Excel) + template | `POST /predict/batch`, `GET /predict/batch/template` |
| NPA early warning (weather based) | `GET /alerts/npa-warning`, `POST /alerts/portfolio-npa-scan` |
| Farmer Health Card PDF | `POST /report/farmer-card` |
| Portfolio analytics, upsell, season comparison | `POST /analytics/portfolio`, `/analytics/upsell-opportunities`, `/analytics/season-comparison` |
| Insurance premium, scheme matcher, crop switch | `POST /tools/insurance-premium`, `/tools/schemes`, `/tools/crop-switch` |
| WhatsApp bot webhook | `GET/POST /webhook/whatsapp` |
| Health check | `GET /`, `GET /health` |

## Quick start

Requires **Python 3.10+**.

```bash
git clone <your-repo-url>
cd agriintel
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env        # optional: only needed for weather alerts / WhatsApp
uvicorn main:app --reload --port 8000
```

Open the interactive docs at <http://localhost:8000/docs>.

No trained model is needed to try it: if `model/artifacts/agriintel_artifacts.pkl` is missing, the API runs in **demo mode** with transparent rule-based estimates (the response contains `"model": "demo"`).

Try it:

```bash
curl -X POST http://localhost:8000/predict/full \
  -H "Content-Type: application/json" \
  -d '{"name":"Ramesh Kumar","crop_type":"paddy","land_size":2.5,"district":"Jorhat",
       "state":"Assam","irrigation_type":"canal","ownership":"owned","season":"kharif"}'
```

Or run the terminal walkthrough of every feature (also regenerates the sample PDF): `python demo.py`

## Training your own model

```bash
pip install -r requirements-train.txt
python model/train.py --data your_data.csv --target annual_income
```

The pipeline: outlier trimming, feature engineering, log-transformed target, Optuna-tuned LightGBM + XGBoost + CatBoost, stacked with a Ridge meta-model. Artifacts are saved to `model/artifacts/` (git-ignored). Restart the API afterwards and it loads them automatically.

### Results

On a private dataset of about 43K rows (not included in this repo), LightGBM reached roughly **21-22% MAPE** against a **78% MAPE** Ridge baseline. That is close to the noise floor of the dataset; getting meaningfully lower would need external data (satellite/weather/market prices). Your numbers will differ with your data.

## Known limitations (read before relying on it)

- **Repayment score is a heuristic.** In demo mode it is a rule-based score. In trained mode the classifier is fit on a *proxy label* derived from income, ownership and irrigation (which are also inputs), so it is circular. It is not a calibrated default probability. It needs real loan-outcome data.
- **AgriScore is a transparent points-based rubric** (income, irrigation, ownership, land size), not a validated credit-risk model.
- **Crop-switch uplift** uses coarse, conservative relative factors capped at +35% of income. Treat it as an illustration, not agronomic advice.
- **Government scheme data** is a simplified snapshot and may be out of date. Always confirm on the official portals.
- District average incomes are hardcoded placeholders.
- NPA warnings use only current weather from OpenWeatherMap (free tier); without an API key it falls back to neutral data.

## Configuration

All settings come from environment variables (see `.env.example`):

| Variable | Purpose |
|----------|---------|
| `WEATHER_API_KEY` | OpenWeatherMap key for NPA warnings |
| `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID` | WhatsApp Business API credentials |
| `WHATSAPP_VERIFY_TOKEN` | Webhook verify token. **Required**, no default |
| `ALLOWED_ORIGINS` | Comma-separated CORS origins. `*` is for local demos only |

## Deployment (Render)

1. Push this repo to GitHub.
2. Render → New Web Service → connect the repo.
3. Build command: `pip install -r requirements.txt`
4. Start command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
5. Add the environment variables above in the Render dashboard (set `ALLOWED_ORIGINS` to your frontend URL).
